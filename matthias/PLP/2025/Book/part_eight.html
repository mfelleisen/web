36 The Pragmatics Question🔗

Can a developer avoid “field not found” and “method not found” errors at run time?

Can a developer avoid “cannot add number to object” errors at run time?

If so, does this help end users of programs?

If so, would this speed up program execution?

36.1 Design Choices🔗

Type systems for class-based languages come in two flavors:

  • nominal class types (Java)

  • structural class types (TypeScript)

For several decades, it appeared that nominal type systems for class-based languages had won. Identifying types with names simplifies how developers work with types on a daily basis, especially when IDEs use types to generate coding hints.

The creation of Type Script quickly changed this perception. Type Script imposes a type system on “naturally grown idioms” in the untyped world of JavaScript, and its creators therefore had to pick the more expressive one of the two solutions.

We will study structural types in preparation of studying the full nature of Type Script’s “types are optional” approach in the next chapter.

36.2 Costs and Benefits🔗

- language implementer: implementing a structural type system is high cost

- language implementer: a type system allows the removal of instructions from the CESK machine

- dev: the type system helps specify and document code

- dev: the IDE can use the type system to support dev’s work; see o.m|n|k

- dev: the type system catches a lot of "typos" while dev’s enter the code into an IDE

- dev: some programs that worked in the untyped world no longer work,

- ... even though they produce correct results
